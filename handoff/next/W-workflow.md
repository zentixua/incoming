# W. Записка в CI и чистка CLAUDE.md

Решение Артёма 22.10 («Делай»). Правила — раздел «Как работаем» в `CLAUDE.md` incoming; источник —
https://code.claude.com/docs/en/best-practices (CLAUDE.md — совет, а то, что должно быть всегда, — механика; раздутый
CLAUDE.md Claude читает через строку).

## 1. Проверка «Записки» в CI
- Отдельный workflow (не `build.yml`: правка описания PR не должна перезапускать сборку и GameTest), события PR
  `opened, edited, synchronize, reopened, ready_for_review`.
- Если PR меняет то, что видит или слышит игрок (`mod/src/main/java/**/client/**`, `**/sound/**`,
  `mod/src/main/resources/assets/**`, скрипты сборки ресурсов в `tools/` — список путей один, в скрипте), в описании
  должен быть раздел `## Записка` с текстом: закон, где верен, ключевые моменты. Правке, которую можно описать одной
  фразой, — одна строка в разделе. Нет раздела — проверка красная с понятной причиной и ссылкой на `TEMPLATE.md`.
- Логика — скрипт в `tools/` с юнит-тестом (пути и разбор описания), workflow только зовёт его.
- В `CLAUDE.md` одной строкой: проверка «Записка» зелёная — условие влития, как «Итог».

## 2. Чистка `CLAUDE.md` incoming (289 строк)
- Для каждой строки вопрос из доков: «уберу — Claude ошибётся?». Нет — убрать. Выводимое из кода, повторы
  `.claude/rules/` (раскладка `tools/` уже в `tools.md`), подробности одной области — в файл правил области, не сюда.
- Не трогать: люди и правила общения, решения Артёма, принципы физики, подводные камни, которые не видны из кода.
- Цель — заметно короче (ориентир ~180 строк) без потери правил; в PR — список убранного и куда перенесено.
- Ревью — свежим агентом: не потерялось ли правило, которое предотвращает ошибку.

Готово: оба PR влиты при зелёном CI и чистом ревью.
