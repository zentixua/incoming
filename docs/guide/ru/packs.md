# Для владельцев серверов и авторов сборок

[English](../packs.md) · Русский

Incoming сообщает другим модам и скриптам, что происходит с каждым ударом, через события NeoForge на игровой шине
событий. Сборка может назначить свою цену ударам, добавить перезарядку, считать попадания для таблицы очков или дать
ведущему игры откликнуться на пуск. Всё это работает на выделенном сервере, в открытом по сети мире и в одиночной игре.

## События ударов

Каждый приказ на удар проходит одни и те же шаги, откуда бы он ни пришёл: с пульта наведения, из команды, со
стационарной пусковой, от ядерного пуска, который ждёт второго ключа или оповещения, или из `/incoming nuke now`.

| Событие (класс в `ua.zentix.incoming.api`) | Когда приходит |
|---|---|
| `StrikeOrderEvent$Request` | Приказ прошёл собственные проверки Incoming (права, правила наведения, ядерные правила, лимит активных ударов, задание и запас пусковой). Отмени событие, чтобы отклонить приказ; ещё ничего не оплачено. |
| `StrikeOrderEvent$Rejected` | Приказ отклонён после запроса: его отменил слушатель или игроку не хватило боеприпасов при оплате. |
| `StrikeOrderEvent$Accepted` | Приказ записан и оплачен. Событие сообщает, сколько в нём снарядов и как они оплачены: сразу из инвентаря игрока, по одному из магазина стационарной пусковой или никак (консоль, командные блоки, операторы, творческий режим). |
| `StrikeRoundEvent$Released` | Снаряд уходит: становится на направляющую или стартует издалека, взлетает МБР, начинается взрыв `nuke now`. |
| `StrikeRoundEvent$Ended` | Снаряд закончил путь: боевая часть сработала, его сбили, он не долетел (разбился до взведения, пуск не удался) или его отозвали либо отменили. Событие также сообщает, вернулись ли боеприпасы за этот снаряд. |
| `NuclearDetonationEvent` | Ядерный взрыв: место, мощность, воздушный или наземный, а также приказ и снаряд, к которым он относится. |
| `GridOutageEvent` | Начинается отключение электричества: выбита подстанция или ядерный взрыв обесточил сеть. |
| `GridRestoreEvent` | Свет вернулся во весь район отключения. Отключение вокруг разрушенной зоны не заканчивается. |

Каждый запрос завершается ровно одним `Rejected` или `Accepted`, а каждый снаряд принятого приказа — ровно одним
`Ended`. Снаряд сохраняет свой идентификатор, пока летит вне загруженного мира, возвращается в него и после
перезапуска сервера. Снаряд, который так и не ушёл (отменённый залп, неудачный пуск, ядерный пуск без второго ключа),
завершается без `Released`. Все события приходят из потока сервера; их значения — простые числа, идентификаторы,
имена и координаты.

Чтобы назначить свою цену или перезарядку, проверь её в `Request`, спиши в `Accepted` и при желании верни в `Ended`.
Incoming не отменяет списания других модов. Не начинай новый удар изнутри слушателя `Request`: такой удар ждёт
следующего тика и получает собственный запрос.

## Пример для KubeJS

KubeJS слушает эти события через `NativeEvents.onEvent`. Этот серверный скрипт отклоняет удары игрока 30 секунд
после его последнего принятого удара:

```js
const Request = Java.loadClass('ua.zentix.incoming.api.StrikeOrderEvent$Request')
const Accepted = Java.loadClass('ua.zentix.incoming.api.StrikeOrderEvent$Accepted')
const last = {}

NativeEvents.onEvent(Request, event => {
  const player = event.getActorId()
  if (player != null && Date.now() - (last[player] || 0) < 30000) event.setCanceled(true)
})

NativeEvents.onEvent(Accepted, event => {
  const player = event.getActorId()
  if (player != null) last[player] = Date.now()
})
```

Игрок видит «Приказ на удар отклонён» над панелью быстрого доступа. Мод на Java может показать свою строку через
`setRefusal`.
