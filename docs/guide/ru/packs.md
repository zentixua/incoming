# Для владельцев серверов и авторов сборок

[English](../packs.md) · Русский

Incoming сообщает другим модам и скриптам, что происходит с каждым ударом, через события NeoForge на игровой шине
событий. Сборка может назначить свою цену ударам, добавить перезарядку, считать попадания для таблицы очков или дать
ведущему игры откликнуться на пуск. Всё это работает на выделенном сервере, в открытом по сети мире и в одиночной игре.

## События ударов

Каждый приказ на удар проходит одни и те же шаги, откуда бы он ни пришёл: с пульта наведения, из команды, со
стационарной пусковой, от ядерного пуска, который ждёт второго ключа или оповещения, или из `/incoming nuke now`.

| Событие (класс в `ua.zentix.incoming.api`) | Когда приходит |
|---|---|
| `StrikeOrderEvent$Request` | Приказ прошёл собственные проверки Incoming (права, правила наведения, ядерные правила, лимит активных ударов, задание и запас пусковой). Отмени событие, чтобы отклонить приказ; ещё ничего не оплачено. |
| `StrikeOrderEvent$Rejected` | Приказ отклонён после запроса: его отменил слушатель или игроку не хватило боеприпасов при оплате. |
| `StrikeOrderEvent$Accepted` | Приказ записан и оплачен. Событие сообщает, сколько в нём снарядов и как они оплачены: сразу из инвентаря игрока, по одному из магазина стационарной пусковой или никак (консоль, командные блоки, операторы, творческий режим). |
| `StrikeRoundEvent$Released` | Снаряд уходит: становится на направляющую или стартует издалека, взлетает МБР, начинается взрыв `nuke now`. |
| `StrikeRoundEvent$Ended` | Снаряд закончил путь: боевая часть сработала, его сбили, он не долетел (разбился до взведения, пуск не удался) или его отозвали либо отменили. Событие также сообщает, вернулись ли боеприпасы за этот снаряд и вёл ли его владелец через камеру. |
| `NuclearDetonationEvent` | Ядерный взрыв: место, мощность, воздушный или наземный, а также приказ и снаряд, к которым он относится. |
| `GridOutageEvent` | Начинается отключение электричества: выбита подстанция или ядерный взрыв обесточил сеть. |
| `GridRestoreEvent` | Это отключение больше не гасит ни один район (другое отключение ещё может гасить часть из них). Отключение вокруг разрушенной зоны заканчивается, только если свет вернули командой. |

Каждый запрос завершается ровно одним `Rejected` или `Accepted`, а каждый снаряд принятого приказа — ровно одним
`Ended`. Снаряд сохраняет свой идентификатор, пока летит вне загруженного мира, возвращается в него и после
перезапуска сервера. Снаряд, который так и не ушёл (отменённый залп, неудачный пуск, ядерный пуск без второго ключа),
завершается без `Released`. Все события приходят из потока сервера; их значения — простые числа, идентификаторы,
имена и координаты. `Request`, `Rejected` и `Accepted` приходят, пока приказ отдаётся, поэтому следующий приказ уже
видит, что предыдущий принят. Остальные события приходят в конце того же тика, в том порядке, в каком всё
произошло. Ядерный взрыв или отключение, которые не относятся ни к одному приказу (от другого мода или сохранённые
до того, как ты добавил свой скрипт), тоже приходят, без идентификаторов приказа и снаряда.

Чтобы назначить свою цену или перезарядку, проверь её в `Request`, спиши в `Accepted` и при желании верни в `Ended`.
Incoming не отменяет списания других модов. Удар, начатый изнутри слушателя `Request`, отдаётся на одном из
следующих тиков, со всеми проверками и собственным запросом.

## Пример для KubeJS

KubeJS слушает эти события через `NativeEvents.onEvent`. Этот серверный скрипт отклоняет удары игрока 30 секунд
после его последнего принятого удара:

```js
const Request = Java.loadClass('ua.zentix.incoming.api.StrikeOrderEvent$Request')
const Accepted = Java.loadClass('ua.zentix.incoming.api.StrikeOrderEvent$Accepted')
const last = {}

NativeEvents.onEvent(Request, event => {
  const player = event.getActorId()
  if (player != null && Date.now() - (last[player] || 0) < 30000) event.setCanceled(true)
})

NativeEvents.onEvent(Accepted, event => {
  const player = event.getActorId()
  if (player != null) last[player] = Date.now()
})
```

Игрок видит «Приказ на удар отклонён» над панелью быстрого доступа. Мод на Java может показать свою строку через
`setRefusal`.

## Результаты команд, статус и метки

Команды ударов возвращают числа, которые читают командные блоки и `execute store result`, поэтому датапак или
ведущий игры могут провести раунд мини-игры с ударами без других модов.

- Команда удара (`/incoming <оружие> …`, `salvo`, `nuke`, `nuke now`, `launcher … fire`) возвращает, сколько снарядов принято в её
  приказ: залп из 12 возвращает 12 на том же тике, хотя его снаряды стартуют в следующие секунды; МБР возвращает 1;
  отклонённый приказ — 0. Строка в чате называет приказ тем идентификатором, который несут события ударов.
- `salvo …` и `nuke …` принимают в конце `tag <имя>`. Метка — имя группы приказов: её могут носить сколько угодно
  приказов от кого угодно и в любом измерении, и она остаётся с их снарядами после перезапуска сервера.
- `/incoming status` перечисляет незавершённые приказы и возвращает число их незавершённых снарядов;
  `status tag <имя>` считает одну группу, `status <игрок>` — приказы одного игрока (только оператор). Снаряд не
  завершён, пока ждёт пуска (остаток залпа, ядерный пуск без второго ключа), пока летит и после попадания, пока
  отрабатывается его взрыв: у обычной боевой части — взрыв, воронка, обрушение, разлитое топливо, обломки и выбитые
  стёкла; у ядерной —
  ударная волна, пока не пройдёт весь свой радиус. Руины, которые появятся позже в чанках, загруженных потом, не
  считаются. У каждого приказа видно, когда прибудет его последний снаряд, или «неизвестно», пока этого не сказать
  (залп ещё стартует, второй ключ, удар ждёт загрузки земли).
- `/incoming clear tag <имя>` отзывает одну группу: оператор, хост и консоль отменяют все её снаряды, ядерные
  тоже; игрок без прав оператора отзывает только свои снаряды в ней, как `/incoming clear`. Пусковые остаются до
  полного `/incoming clear`.

Игрок без прав оператора видит в `status` только свои приказы. Когда `status tag <имя>` возвращает 0, каждый снаряд
группы завершён (его `StrikeRoundEvent$Ended` придёт до конца этого тика) и его взрывы закончились.

```mcfunction
# начать волну
execute store result score #wave arena run incoming salvo rocket 20 25 at 120 70 -340 tag wave1
# каждую секунду: снаряды волны, которые ещё ждут, летят или взрываются
execute store result score #left arena run incoming status tag wave1
```

## Ведущий игры

Incoming несёт памятку для ИИ-ведущего [Almighty](https://github.com/zentixua/almighty):
`data/incoming/almighty/notes/strikes.md`. В ней для ведущего команды ударов, электросети и радиации и что каждая
возвращает, события ударов, за которыми могут следить его правила, и два готовых правила: волны налёта, где каждая
следующая начинается, когда `status tag` прошлой вернёт 0, и отклик на ядерный взрыв. Датапак заменяет памятку своим
файлом по тому же пути; пустой файл убирает её.

## Правила мира для мини-игры

`/incoming rule` (операторы, консоль, командные блоки и функции) меняет правила мира, пока мир идёт, и сохраняет их в
файл настроек мира; что задаёт каждое правило, сказано в [списке правил](commands.md#правила-мира). Изменение действует
для приказов, отданных после него: волна, которая уже в воздухе, идёт по правилам, при которых её заказали, поэтому
включить правила обратно сразу после волны безопасно. Когда `world.block_damage`, `world.shatter_glass`, `world.fire`,
`world.debris_stay`, `world.collapse` и `grid.enabled` выключены, обычные удары не меняют ни одного блока и не
отключают свет. У ядерных ударов свои правила: на арене выключи `nuclear.enabled`.

```mcfunction
# раунд на арене: удары ранят игроков, но карта остаётся как есть
incoming rule world.block_damage false
incoming rule world.shatter_glass false
incoming rule world.fire false
incoming rule world.debris_stay false
incoming rule world.collapse false
incoming rule grid.enabled false
incoming rule nuclear.enabled false
execute store result score #wave arena run incoming salvo rocket 20 25 at 120 70 -340 tag wave1
```

`/incoming rule <ключ>` возвращает значение числом (вкл 1, выкл 0), так что функция может проверить состояние арены через
`execute store result`.

## Достижения и статистика

Достижения и статистика Incoming — ванильные, поэтому моды заданий (задания на достижение и статистику в FTB Quests),
таблицы очков, датапаки и ведущий игры, который следит за достижениями, берут их как есть. Что видят игроки:
[Достижения и статистика](progress.md).

| Достижение | Триггер критерия | Когда выдаётся |
|---|---|---|
| `incoming:strikes/root` (вкладка) | `minecraft:inventory_changed`, `incoming:round_released` | у игрока любой предмет Incoming или он запускает боеприпас |
| `incoming:strikes/first_strike` | `incoming:round_released` | запущен боеприпас игрока |
| `incoming:strikes/camera_strike` | `incoming:camera_guided_hit` | срабатывает боеприпас, который игрок вёл через его камеру |
| `incoming:strikes/first_interception` | `incoming:round_intercepted` | ЗРК или оружие игрока сбивает вражеский боеприпас |
| `incoming:strikes/nuclear_survivor` | `incoming:nuclear_survived` с `overpressure_psi` не меньше 5 | игрок жив, когда прошла ударная волна ядерного взрыва, накрывшая его с давлением от 5 psi |
| `incoming:strikes/lights_back` | `incoming:blackout_restored` | отключение заканчивается, пока игрок стоит в одном из его районов, и в этом районе снова есть свет |

Свои достижения могут брать эти триггеры с такими условиями (все необязательные, кроме обычного `player`):

| Триггер | Условия |
|---|---|
| `incoming:round_released` | `weapon`: `drone`, `loiter`, `rocket`, `missile`, `bunker` или `nuke` |
| `incoming:camera_guided_hit` | `weapon` |
| `incoming:round_intercepted` | `weapon` (сбитого боеприпаса), `by_sam` (true — ЗРК, false — собственное оружие игрока) |
| `incoming:nuclear_survived` | `overpressure_psi`, `yield_kt` (диапазоны чисел, например `{"min": 5}`) |
| `incoming:blackout_restored` | `nuclear` (true — отключение, которое ядерный взрыв вызвал на всю свою досягаемость) |

| Статистика | Критерий таблицы очков | Что считает |
|---|---|---|
| `incoming:rounds_launched` | `minecraft.custom:incoming.rounds_launched` | боеприпасы, которые запустил игрок |
| `incoming:rounds_launched.<weapon>` | `minecraft.custom:incoming.rounds_launched.drone` и остальные id оружия | то же для одного оружия |
| `incoming:interceptions` | `minecraft.custom:incoming.interceptions` | вражеские боеприпасы, которые сбил игрок |
| `incoming:nuclear_detonations_witnessed` | `minecraft.custom:incoming.nuclear_detonations_witnessed` | ядерные взрывы, до которых игрок был в досягаемости (там бьются стёкла или обжигается кожа) |

- Боеприпас засчитывается владельцу, тому же игроку, которого называют события ударов, и только пока он в игре: для
  вышедшего ничего не копится. Боеприпасы из консоли, командных блоков, с пусковых без владельца и от ненастоящих
  игроков со своим собственным именем никому не засчитываются. `/execute as <игрок>` делает боеприпас боеприпасом
  этого игрока, как и машина, действующая под профилем самого игрока (механический манипулятор Create за своего
  владельца), — так же, как стационарная пусковая и права.
- Сбитый боеприпас засчитывается владельцу ЗРК или игроку, чьё оружие его сбило, если боеприпас не его и не его
  команды (по `/team`, как ЗРК решает, по кому стрелять).
- «Выстоять» начинается, когда фронт волны действительно накрывает игрока: давление в его точке берётся из модели
  взрыва, в укрытии или нет, и достижение ждёт, пока там пройдёт фаза сжатия, плюс одна секунда, чтобы отброшенное
  тело приземлилось. Игрок, ушедший до фронта, отменённый удар, творческий режим и режим наблюдателя не получают
  ничего; смерть, выход или смена измерения до этого момента отменяют достижение.
- «Да будет свет» следует районам сети: район игрока должен был погаснуть в этом отключении и снова получить свет, когда оно
  закончится (другое отключение над ним оставляет его тёмным).

```mcfunction
# боковая панель сбитых боеприпасов
scoreboard objectives add shot_down minecraft.custom:incoming.interceptions "Сбито"
scoreboard objectives setdisplay sidebar shot_down
```

Достижение датапака за то, что игрок пережил 20 psi от взрыва мощностью как у МБР:

```json
{
  "criteria": {
    "close": {
      "trigger": "incoming:nuclear_survived",
      "conditions": { "overpressure_psi": { "min": 20 }, "yield_kt": { "min": 10 } }
    }
  }
}
```

## Права

Кто может запускать, решают узлы прав NeoForge. Без мода прав они следуют настройкам
(`launch.designator_for_everyone`, `nuclear.ops_only`, права оператора), поэтому ничего не меняется. Мод прав,
который стал обработчиком прав NeoForge (LuckPerms устанавливает себя, когда выбран обработчик NeoForge по умолчанию),
может дать или запретить каждое право игроку или группе, а через свои контексты и в отдельном измерении.

| Узел | Без мода прав | Что разрешает |
|---|---|---|
| `incoming.launch` | всем при включённом `launch.designator_for_everyone`, иначе операторам | пульт, его карту и отбой, команды ударов |
| `incoming.launch.<оружие>` | всем | одно оружие: `drone` («Шахед-136»), `loiter` («Ланцет»), `rocket` («Град»), `missile` (крылатая ракета), `bunker` (B-2 с бомбой), `nuke` (МБР) |
| `incoming.nuclear` | всем при выключенном `nuclear.ops_only`, иначе операторам и хозяину одиночного или открытого по сети мира | ядерные приказы, включая ядерную боевую часть на крылатой ракете или B-2, и поворот второго ключа |
| `incoming.launcher.link` | как `incoming.launch` | привязку пусковых к пульту и задания для них |

- Узлы действуют на каждый приказ игрока: пульт, команды, которые он вводит (и оператор тоже, и через `/execute as`),
  пусковые, привязанные к его пульту, и его пусковую, которая стреляет по правам хозяина. Приказ, начатый внутри
  события другого приказа, выполняется тиком позже и тогда спрашивает снова. Ядерный пуск, ждущий второго ключа,
  ещё раз спрашивает хозяина, когда ключ повёрнут: если право за это время отняли, пуск отменяется и боеприпасы
  возвращаются. `nuke now`, выполненный тиком позже, тоже спрашивает снова, и ему по-прежнему нужен оператор.
- Консоль, командные блоки и функции, которые они запускают, и пусковые, поставленные командой (без хозяина), не
  спрашиваются. Летящему ядерному удару, который они отдают за игрока (`/execute as`), нужны права этого игрока;
  `nuke now` — нет.
- При выключенном `nuclear.enabled` ядерное оружие не запускает никто, что бы ни говорили узлы; носитель, который уже
  предупреждает цель, не взлетает, и боеприпасы возвращаются (хозяину не в игре — когда он зайдёт). `incoming.nuclear` не делает игрока оператором: ему всё
  равно нужен второй ключ от игрока рядом, и только операторы и хозяин отменяют все ядерные удары, перенацеливают
  ядерную боевую часть и выбирают место пуска на карте. Повернуть второй ключ просят только тех, кому это можно.
- Мод прав нельзя спросить об игроке не в игре, не рискуя остановить сервер, поэтому пусковая, чей хозяин не в игре,
  следует столбцу «Без мода прав»: то, что мод прав разрешает или запрещает хозяину, действует на его пусковую, пока он
  в игре.
- Отклонённый приказ показывает причину над панелью быстрого доступа; пусковая показывает её в строке состояния.
  Игроку без `incoming.launch` и без прав оператора команда `/incoming` не доступна вовсе.

Например, в LuckPerms:

```
/lp group default permission set incoming.launch.bunker false
/lp group default permission set incoming.launch.nuke false
/lp group veterans permission set incoming.launch.nuke true
/lp group veterans permission set incoming.nuclear true
```

## Защита приватов

Моды приватов, которые защищают чанки от взрывов (Open Parties and Claims, FTB Chunks и любой другой мод, который
отсеивает урон от взрывов), защищают их от всех изменений блоков, которые делает Incoming: взрыва боевой части, её
воронки, выбитых стёкол, огня от огненного шара и горящего топлива, следов осколков, канала и подземной полости бомбы
B-2, обрушения зданий и их обломков, упавших обломков; у ядерного взрыва ещё и вспышки (опалённой земли и стен, огня от
неё, опалённого цвета биомов), руин за волной, воронки, поваленных деревьев и дальнего ландшафта в Voxy или Distant
Horizons. В защищённом чанке волна, свет, звук и ранения такие же, как везде; остаются только блоки.

- Мод приватов решает так же, как для любого взрыва: в Open Parties and Claims это защита привата от взрывов, в FTB
  Chunks настройка команды «Allow explosions». У обычного удара источник взрыва его снаряд. У ядерного взрыва
  источника нет, поэтому FTB Chunks защищает от него только с включённым `protect_unknown_explosions` (так по
  умолчанию).
- Ядерный взрыв решает судьбу чанка окончательно: чанк, который оказался защищён, когда до него дошла вспышка или
  волна, сохраняет блоки на весь этот взрыв, даже если приват снимут через мгновение, а приват, поставленный после
  вспышки, всё равно не пускает волну. Решение сохраняется вместе с миром: руины, которые строятся после перезапуска
  или когда далёкий чанк загрузится позже, следуют ему. Следующий взрыв решает заново.
- Ядерные руины меняют чанк целиком: мод, который защищает часть чанка, сохраняет от ядерных руин весь чанк. Обычный
  удар оставляет ровно защищённые блоки.
- Дальний ландшафт чанка, который не загружен, показывает руины, если этот чанк ещё не оказался защищён; сам чанк
  решается, когда загрузится, и дальний вид догоняет его, когда чанк увидят.
- Огонь, который распространяется потом, это обычный игровой огонь: перейдёт ли он в приват, решают настройки огня мода
  приватов. Отключение электричества не урон блокам: приват не спасает подстанцию от выхода из строя, и затемнение
  доходит и до чанков в привате.

Для авторов модов: Incoming спрашивает через `ExplosionEvent.Detonate` со взрывом класса
`ua.zentix.incoming.api.ClaimQuery` (нулевой радиус, без существ), в списке блоков которого позиции, которые сейчас
изменятся, только в уже загруженных чанках. Это вопрос, а не взрыв: слушатель, который сам реагирует на взрывы
(эффекты, звуки), должен его пропускать.

## Красный камень

Два блока дают сигнал красного камня, так что механизмы и компьютеры реагируют без всяких скриптов. Оба дают слабый
сигнал силой 15 со всех шести сторон, как датчик дневного света: его читают пыль, повторители, лампы, поршни, двери,
Redstone Link из Create и `redstone.getInput(side)` из ComputerCraft рядом с ними; сквозь блок, которого они касаются,
он не проходит. Соседи узнают об изменении в тот же тик, наблюдатели тоже. В одиночной игре, открытом по сети мире и на сервере всё
одинаково.

| Блок | Сигнал есть | Сигнала нет |
|---|---|---|
| ЗРК | последний обзор его радара (каждые полсекунды) видел чужой снаряд, стреляет он по нему или нет | чужих снарядов в поле зрения радара нет; сплошная крыша над ЗРК его ослепляет |
| Трансформаторная подстанция | она работает (гудит) | она выбита (искры и горящее масло), пока в её район не начнёт возвращаться свет |

- Компаратор у ЗРК по-прежнему показывает запас. ЗРК без хозяина считает чужим любой снаряд; ЗРК без ракет сигнал
  всё равно даёт. Подробнее: [Оборона](defense.md#красный-камень).
- Сигнал подстанции следует за самой подстанцией, а не за её кварталом: отключение от другой подстанции над ней сигнал
  не убирает. Подробнее: [Блэкаут](blackout.md).
- Блок в незагруженном чанке сохраняет сигнал, с которым был сохранён, и обновляет его в течение секунды, как только
  чанк заработает. Ближе 32 блоков к незагруженной земле соседи узнают об изменении, когда она загрузится: иначе
  мгновенное обновление схемы загружало бы чанки посреди тика сервера.

Дверь бункера, которая закрывается по тревоге, на Create: приставь Redstone Link (передатчик) к ЗРК, а приёмник на той
же частоте поставь у бункера. Приёмник питает реверсивный редуктор (Gearshift) между валом и механическим поршнем,
который держит стену-дверь: пока в небе чужие цели, редуктор меняет направление вращения и стена задвигается; когда
небо чисто, открывается снова. Компьютер ComputerCraft, к задней стороне которого приставлен ЗРК, сделает то же в скрипте:

```lua
-- ЗРК позади компьютера, сирена или схема двери слева
local function check()
  local alarm = redstone.getInput("back")
  redstone.setOutput("left", alarm)
  print(alarm and "Воздушная тревога" or "Небо чисто")
end
check()
while true do
  os.pullEvent("redstone")
  check()
end
```

## Блоки из других модов

Как блок держит удар, задают данные, которые датапак или мод может дополнить: карта данных — через что проходят бомба и
приложенный заряд, теги блоков — что ломает ударная волна, и теги блоков — что поджигает жар взрыва. Файл в твоём
датапаке по тому же пути добавляет свои записи к записям Incoming (блок или `#тег`); с `"replace": true` в начале файла
он вместо этого отбрасывает записи Incoming. Удары, отданные после `/reload`, берут новые данные.

### Материал: `incoming:penetration`

`data/incoming/data_maps/block/penetration.json` задаёт блоку материал:

| Поле | Значения | Что задаёт |
|---|---|---|
| `kind` | `soil`, `rock`, `concrete`, `fluid`, `stop` | среду, через которую идёт бомба B-2 (уравнения Янга): грунт сразу под `concrete` вдвое твёрже на первых 5 блоках; `fluid` тормозит бомбу только плотностью; `stop` останавливает бомбу и любой заряд |
| `s` | число | проницаемость по Янгу, больше — мягче (для `fluid` — плотность, кг/м³). В ванили: земля 12, песок 7,5, гравий 5, камень и бетон 0,84, глубинный сланец 0,67 |
| `breach` | `earth`, `poor`, `rock`, `dense`, `reinforced` | насколько трудно приложенному заряду пробить его (FM 5-250 армии США): грунт; дерево и слабая кладка; камень, кирпич и простой бетон; плотный бетон; железобетон. Без поля: `soil` — грунт, `rock` и `concrete` — камень |
| `thickness` | метры, 1 если поле не указано | сколько материала стоит за одним целым блоком: ванильный блок бетона — стена в 0,2 м, доска — 0,04 м досок. Плиты, ступени и другие неполные блоки считают только ту часть пути, что внутри их формы |

Запись меняет, насколько глубоко в блок уходит бомба B-2, насколько далеко заряд любой боевой части, взорвавшейся о
блок, пробивает его в комнату или пещеру за ним, и дробит ли блок подземный взрыв бомбы: блоки вида `rock` или
`concrete` вокруг заряда становятся гравием (природный камень — булыжником или глубинным булыжником). Блок без записи
для бомбы считается кирпичом (`s` 1, целый метр), не дробится (сундуки и механизмы остаются), а заряду сопротивляется по
инструменту, которым его добывают: топор — как дерево, лопата или мотыга — как грунт, кирка до твёрдости булыжника —
как камень, всё твёрже — как железобетон. Блок со взрывоустойчивостью 1200 и выше не пробивает ни один заряд.

Железобетон из мода как стена бункера, целый метр железобетона в каждом блоке:

```json
{
  "values": {
    "examplemod:reinforced_concrete": {
      "kind": "concrete",
      "s": 0.84,
      "breach": "reinforced",
      "thickness": 1.0
    }
  }
}
```

С ней бомба B-2 уходит в такой бетон примерно на 4 блока при игровых скоростях полёта (примерно на 9 при
настоящих, пресет `REAL`), тогда как ванильный бетон она проходит примерно на 20 блоков. Боевая часть крылатой ракеты
пробивает из него стену до 2 блоков в комнату за ней, «Шахеда-136» — в 1 блок, «Града» и «Ланцета» — ни одной.

### Классы прочности: теги `incoming:nuke_*`

Ударная волна ломает блок, как только её избыточное давление превышает его порог; порог каждого блока отличается на
±15 % в зависимости от места, поэтому ряд одинаковых блоков ломается не по линейке. Те же классы действуют для волны
любой боевой части, ядерной и обычной (короткой волне обычного заряда нужен ещё и достаточный импульс). В ядерной
волне это пороги стены или перекрытия толщиной в один блок: в два блока они держат вдвое большее давление, в три — в
3,5 раза, а стена, обращённая к взрыву, принимает более сильное отражённое давление.

| Тег | Ломается при | Ванильные блоки в нём |
|---|---|---|
| `incoming:nuke_fragile` | 0,8 psi | стекло и стеклянные панели, факелы, фонари, свечи, цветочные горшки, паутина, слои снега |
| `incoming:nuke_plants` | 8 psi, когда волна срывает дёрн; свет ядерного взрыва сжигает их и дальше | трава, папоротники, цветы, саженцы, посевы, лианы |
| `incoming:nuke_light` | 4 psi | двери, заборы, люки, доски, шерсть, кровати, таблички, сундуки, бочки, книжные полки |
| `incoming:nuke_masonry` | 12 psi | кирпичи, каменные кирпичи, булыжник, гладкий камень, бетон |
| `incoming:nuke_ground` | 15 psi, но толща земли выдерживает волну и заслоняет то, что за ней; воронка её выкапывает | земля, песок, гравий, камень, глубинный сланец, терракота, руды, лёд |

Блок из нескольких тегов берёт первый в таком порядке: `nuke_ground`, `nuke_fragile`, `nuke_plants`, затем листва
(`minecraft:leaves`, 2 psi), стволы деревьев (`minecraft:logs`, они падают по закону вывала леса:
`incoming:nuke_conifers` — как хвойный лес, который держится крепче, остальные — как лиственный), `nuke_light`,
`nuke_masonry`. Блок без этих тегов ломается по твёрдости: до 0,5 — при 1 psi, до 3 — при 5 psi, до 6 — при 12 psi, до
9 — при 25 psi, что твёрже — никогда. Блоки с твёрдостью 50 и выше и неразрушимые (обсидиан, коренная порода) не
ломаются никогда, какие бы теги у них ни были. Вспышка ядерного взрыва метит освещённые грани: `incoming:nuke_chars`
она обугливает дочерна (дерево, шерсть, сено), на `incoming:nuke_soots` оставляет копоть (кладка, бетон, терракота).

Стена из листового металла из мода как лёгкая постройка, в `data/incoming/tags/block/nuke_light.json`:

```json
{
  "values": [
    { "id": "examplemod:sheet_metal_wall", "required": false }
  ]
}
```

Тогда стена из неё толщиной в один блок ломается примерно при 4 psi (от 3,4 до 4,6 в зависимости от места), а не при
пороге своей твёрдости: 12 psi у блока твёрдости железного блока. Оставляй `"required": false` у блоков других модов:
если такого мода нет, запись без него опустошает весь тег, вместе с дверями, досками и сундуками самого Incoming. В
карте данных несуществующий блок пропускает только свою запись.

### Возгорание: теги `incoming:pulse_*`

Жар взрыва поджигает только тонкое сухое топливо; каждому классу нужно своё количество тепла.

| Тег | Топливо | Ванильные блоки в нём | Поджигает |
|---|---|---|---|
| `incoming:pulse_paper` | бумага | книжные полки, кафедры | ядерная вспышка, огненный шар топлива |
| `incoming:pulse_fabric` | ткань | шерсть, ковры, кровати, флаги | ядерная вспышка, огненный шар топлива |
| `incoming:pulse_dry` | сухие растения | сено, блоки сушёной ламинарии, мёртвые кусты, строительные леса | ядерная вспышка, огненный шар топлива |
| `incoming:pulse_grass` | тонкие растения: всё из `pulse_dry` и `nuke_plants`, азалии, бамбук | | огненный шар топлива |
| `incoming:pulse_leaves` | листва | листва | огненный шар топлива |

Вспышка ядерного взрыва поджигает только бумагу, ткань и сухие растения, а ещё дёрн засушливых биомов; живая трава,
листва и дерево обугливаются и дымят, но не загораются. Огненный шар горящего топлива «Шахеда-136» или крылатой ракеты
поджигает все классы из таблицы, но только блоки, которые может сжечь ванильный огонь; блок без этих тегов считается
травой, если ванильный огонь быстро по нему распространяется, а иначе от такой короткой вспышки не загорается (дерево
только обугливается).

Тюк соломы из мода как сухое топливо, в `data/incoming/tags/block/pulse_dry.json`:

```json
{
  "values": [
    { "id": "examplemod:straw_bale", "required": false }
  ]
}
```

Тогда ядерная вспышка поджигает его как сено, а огненный шар топлива — как сухую траву, если мод делает тюк горючим,
как сено. Чтобы он ещё и ломался как сено, добавь его и в `incoming:nuke_light`.
