## Source assessment

- **Physical and numerical behavior:** `GroundDust.java:1010` adds per-instance moment storage; `:1037` changes only the ownership/allocation of the six existing tables. Each positive-age, positive-total lifetime query starts with all 240 double cells zeroed, including wave-phase weights and weighted tops. The ring order, arithmetic, mass/width laws, front clipping, thresholds and optical-depth reduction remain unchanged. There is no cached optical-depth answer indexed by age, so rewinding or repeating an age recalculates the same sums. A zero-age return cannot contaminate the next valid query because that query clears first. Existing `nodeT`/`settlingTime` caches recalculate when the age changes (`:796`, `:845`).
- **Lifetime versus rendering:** only `tau` passes `levels=false` (`GroundDust.java:1426`); its private callback reduces scalar optical depth. That route stops at `:1088` before `open`, `drift`, `level`, relief reads or a consumer supplied by rendering. All `blobs`, `probe` and `maintain` routes still pass `levels=true` and allocate their own moment tables (`:951`, `:960`, `:1006`). `CloudModel` constructs separate ground and crushing dust objects (`CloudModel.java:425`), combines their lifetimes (`:429`), and emits them separately (`:956`). No changed particle count, emission order, color, opacity/temperature handoff, sound or terrain path was found.
- **Callbacks and ownership:** the new scratch tables never escape `GroundDust`. The lifetime route calls fixed numerical methods and the scalar reduction; `CloudModel.Air` and its `LocalWind` are records, not user-overridable wind callbacks. Render callbacks remain local-table owners even if a consumer queries optical depth again. Actual `FarBlasts.Event.emit` callbacks forward values to the smoke sink (`FarBlasts.java:348`); source sampling happens before worker planning (`SmokePuffs.java:495`, `SmokePreparation.java:137`). The worker receives sealed drawing inputs (`SmokePuffs.java:595`), not a task that invokes lifetime queries. No supported concurrent/reentrant lifetime access was found. The model already has mutable interpolation/settling caches and is not a general thread-safe API; this patch does not introduce cross-thread publication.
- **Memory:** the added arrays have a fixed shape per nonempty dust instance, with no static map or additional world/consumer reference. On typical compressed-reference HotSpot layouts, six 5x8 tables plus the holder are about 2.7 KB per instance, roughly 5.4 KB for the two populated instances in a cloud; this is a layout estimate, not a measured heap delta. They remain reachable for the model's lifetime. One retained `aloft` table is unused by `levels=false`, but this is small constant storage, not a budget blocker. Existing event/source/preparation cleanup remains in `FarBlasts.tick/reset`, `SmokeGrid.tick/reset` and `SmokePreparation` pruning/reset. Sound-pending event retention is pre-existing; no new retention root is added.
